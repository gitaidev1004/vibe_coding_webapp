# 3장 실습 체크리스트 - 요구사항 -> 유스케이스 -> 아키텍처 -> ERD -> API 명세 완성하기

2장에서 완성한 PRD와 요구사항 정의서를 바탕으로 아래 순서에 따라 설계 산출물을 완성한다.

## 진행 순서
- [ ] 1. 요구사항 정의서의 기능 요구사항 각각에 대해 usecase_spec_template.md 형식으로
      유스케이스 명세서를 작성한다. (최소 3건)
- [ ] 2. 3.3절의 아키텍처 패턴 중 하나를 선택하여, 실습 프로젝트에 적용할 계층 구조를
      한 문단으로 정리한다.
- [ ] 3. erd_data_dictionary_template.csv 형식으로 각 테이블의 컬럼, 자료형, PK/FK를
      정의한다. (ch03/08_erd/schema.sql 을 참고하여 최소 3개 테이블)
- [ ] 4. build_erd_db.py를 참고하여 작성한 ERD가 실제로 오류 없이 생성되는지
      SQLite로 검증한다.
- [ ] 5. 요구사항 중 최소 3건에 대해 api_spec_template.md 형식으로 API 명세서를
      작성한다.
- [ ] 6. validate_openapi.py의 점검 로직을 참고하여, 작성한 API 명세에 CRUD 메서드와
      성공/오류 응답이 빠짐없이 정의되었는지 점검한다.
- [ ] 7. 2장에서 작성한 rtm_template.csv에 유스케이스, 화면(가안), API 열을 채워
      넣는다.

## 완료 기준
- 모든 기능 요구사항에 대응하는 유스케이스가 하나 이상 존재한다.
- ERD의 모든 테이블에 기본키(PK)가 있고, 관계가 있는 테이블에는 외래키(FK)가
  명시되어 있다.
- 모든 API 명세에 성공 응답과 최소 하나의 오류 응답이 정의되어 있다.
